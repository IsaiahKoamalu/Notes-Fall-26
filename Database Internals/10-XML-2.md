## Overview
- XML: Extensible Markup Language
- software and hardware independent tool for storing and transporting data.
- both human and machine readable
- self-descriptive
- Does not "do" anything, just designed to store data in an easy-to-understand manner.
EX: `note.xml`
```xml
<note>
	<to>John</to>
	<from>Lisa</from>
	<heading>Reminder</heading>
	<body>Don't forget about me!</body?
</note>
```
- The note is self-descriptive but contains no executable code
- Just wraps information in tags

## Formatting & Viewing XML
- Someone must write a piece of software to send, receive store, or display it.
	- since it is just information wrapped in tags

## XML vs. HTML
- Both designed with different goals
- XML &rarr; carry data with focus on what data is
- HTML &rarr; display data with focus on how data looks
- XML tags are not predefined like HTML tags are

## No Predefined Tags
- Tags in the previous example are not defined in any XML standard.
- The tags are "invented" by the author of the XML document.
- So the author must define both the tags and the document structure.

## XML is Extensible
- Most XML applications work as expected even if new data is added (or removed).
- So you could create a newer version of `note.xml` by adding `<date>` and `<hour>` elements and a removed `<heading>`.
- With the way XML is constructed, older versions of the application can still work.

## XML Simplifies Things
- Simplifies data sharing
- Simplifies data transport
- Simplifies platform changes
- Simplifies data availability
- Stores data in plain text
	- this provides a software-hardware independent way of storing, transporting, and sharing data.
- Makes it easier to expand or upgrade to new operating systems, new applications, new browsers, without losing data.
- Data can be available to all kinds of 'reading machines' like people, computers, voice machines, news feeds, etc.

## How XML can be Used
- Used in many aspects of web development.
- Separate data from presentation.

## Separating Data from Presentation
- XML does not carry any information about how to be displayed.
- Same XML data can be used in many different presentation scenarios.

## XML is a Complement to HTML
- In many applications, XML is used to store or transport data, while HTML is used to format and display the same data.
- EX: an XML document containing containing a news article including the title, author, date, and article content &rarr; HTML page including some JS code can to display any article contained in an XML file following an expected data format.

## XML Separates Data from HTML
- Should not have to edit an HTML file when when the data changes while displaying it.
- With XML the data can be stored in separate XML files.
- With a few lines of JS code you can read an XML file and update the data content of any HTML page.

## XML Tree
- XML documents form a tree structure that starts at "the root" and branches to "the leaves".
	- documents are formed as element trees
- Start at root element then branch to child elements.
- All elements can have sub elements (child elements)
```XML
<root>
	<child>
		<subchild>.....</subchild>
	</child>
</root>
```

## XML Elements: Text vs. Attributes
- All elements can have text content.
	- Ex: `Harry Potter`
- Elements can also have attributes
	- EX: `category="cooking"`

## XML Syntax
- Uses mostly self-describing syntax.
- A prolog defines the XML version & character encoding.
	- `<?xml version="1.0" encoding="UTF=8"?>`
- The next line is the root element of the document.
	- `<bookstore>`
- The next line starts a book element.
	- `<book category="cooking">`

## Syntax Rules: Root Elements
- XML documents must have a root element
	- must contain one root element that is the parent of all other elements.

## Syntax Rules: The Prolog and Character Sets
- The XML prolog is optional
	- if it exists it must come first in the document
- XML docs can contain international characters.
- To avoid errors, encoding should be specified, or save the XML files as a UTF-8
	- UTF-8 is the default character encoding for XML documents.

## Syntax Rules: Closing Tags
- All XML elements must have closing tag
	- In HTML, some elements might work, even with a missing closing tag.
- In XML it is illegal to omit the closing tag.

## Syntax Rules: Tags are Case Sensitive
- The tag `<Letter>` is different from the tag `<letter>`
- Opening and closing tags must be written in the same case.
- Note: "Opening and closing tags" are often referred to as "Start and end tags".

## Syntax Rules: Proper Nesting
- Elements must be properly nested
- Unlike HTML, in XML all elements must be properly nested within each other.

## Syntax Rules: Attributes
- XML elements can have attributes in name/value pairs just like in HTML
- The attribute values must always be quoted.
**Incorrect:** `<note date=12/11/2007>`
**Correct:** `<note date="12/11/2007">`

## Syntax Rules: Entity Reference
- Some characters have a special meaning in XML.
**Incorrect:** `<message>salary < 1000</message>`
**Correct:** `<message>salary &lt; 1000</messages>`
